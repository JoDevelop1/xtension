# Xtension v0.6.13

This release moves draft insertion on Windows to the native input path described in `SENDINPUT_ISTRUSTED_TEST.md`.

## Native, trusted browser input

- Generated replies, corrections, translations, suggestions, and draft replacements are delivered by the installed Windows connector through `SendInput`.
- Chrome and Edge create the resulting DOM events themselves; the verified local harness reports `Event.isTrusted === true` for `keydown`, `beforeinput`, `input`, and `keyup`.
- Streaming still receives the model output incrementally, but it no longer mutates the X/Twitter composer with synthetic DOM updates. The final result is inserted once through native input.

## Target safety

- The helper validates the expected browser and page title immediately before injection.
- It pins the foreground native window and focused child handle and refuses the operation if either changes.
- A native failure never falls back silently to the old DOM path once native input has been advertised.

The Windows low-level `LLKHF_INJECTED` flag remains observable to native hooks. This release fixes browser DOM provenance; it does not claim that injected input is identical to physical hardware at every operating-system layer.
